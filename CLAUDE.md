## What this project is

**Mandarin**: a Windows-native, fully offline, zero-click file converter, inspired by
"Tangerine for Mac". No floating panel or icon sits on the desktop — Mandarin lives only
in the tray. Hold Shift while dragging any file, anywhere, to bring up the radial format
wheel at the cursor; hold Shift+Alt for advanced tools (compress, crop, trim, split,
merge, strip metadata). The Explorer "Convert with Mandarin" right-click verb opens the
same wheel without needing Shift.

Full phase-by-phase roadmap lives in `PLAN.md` — always check which phase we're on
before starting work, and don't jump ahead to a later phase without confirmation.

## Stack

- .NET 8, WPF, MVVM via `CommunityToolkit.Mvvm`.
- Image conversion: Magick.NET (ImageMagick).
- Video/audio conversion: FFmpeg, invoked as a bundled local `ffmpeg.exe` process (not a
  wrapper library) — keep the process-call logic isolated behind an interface so the
  binary invocation is easy to swap or mock in tests.
- PDF: `PdfPig` (text extraction, PDF→TXT/DOCX, Apache 2.0), `PDFtoImage` (PDFium-backed
  rasterization, PDF→JPG/PNG at 300 DPI, MIT), `PdfSharpCore` (PDF generation, TXT→PDF,
  MIT). No GPL/AGPL exposure (PDFium itself is BSD-3), chosen specifically to avoid a
  Ghostscript dependency.
- Archives: SharpCompress.
- Localization: hand-rolled `Strings.resx`/`Strings.tr.resx` + a typed `Strings` wrapper
  in `Mandarin.App.Resources` (not VS-generated `Resources.Designer.cs` — written by
  hand for build-tool independence). Scoped to static XAML-authored UI text (dialog
  titles, buttons, tray menu, toast titles); dynamic error messages generated by Core are
  English-only today, since Core has no UI/localization concern per hard rule 1 —
  localizing those would need Core to return message keys instead of formatted strings,
  which hasn't been done.
- Distribution: self-contained single-file `.exe`, no MSIX (see Packaging below).

## Hard rules

1. **`Mandarin.Core` never references WPF or any UI framework.** Conversion logic must
   be usable from a CLI or a different front-end later.
2. **New format = new `IConverter` implementation.** Never add formats via a growing
   if/else or switch chain — use the strategy/plugin pattern already established.
3. **No network calls, anywhere, ever**, except the manual "Check for updates" button in
   Phase 6, and only when the user explicitly clicks it. No analytics, no telemetry, no
   silent pings.
4. **Never crash on bad input.** Corrupt files, missing codecs, unsupported conversions
   → catch, show a clear user-facing message, log internally, keep the app alive.
5. **Don't copy Tangerine's actual branding/logo.** Original icon/palette only
   (orange/mandarin theme is fine conceptually, the artwork must be our own).
6. Every phase must leave the app in a buildable, runnable state. Don't leave partial/
   broken builds between phases.

## Conventions

- C# nullable reference types enabled.
- Async all the way for conversion operations; never block the UI thread on a
  conversion.
- User-facing strings go through the localization resource files (English + Turkish),
  not hardcoded in views/viewmodels.
- Settings persisted as JSON under `%AppData%\Mandarin`.
- **All UI styling comes from `Themes/`** (merged in `App.xaml`): `Theme.xaml` holds the
  metric/typography tokens and a templated style for every control the app uses;
  `Tokens.Light.xaml` / `Tokens.Dark.xaml` hold the colours. Views must not hardcode hex
  colours, font sizes or corner radii — add or reuse a token. Code-built UI (radial wheel
  petals, toast state colours) reads the same tokens through `Themes/ThemeBrushes.cs`.
- **Light/dark**: `ThemeManager.Apply("system"|"light"|"dark")` swaps the token dictionary
  at index 0 of the app resources, so **every colour must be referenced with
  `DynamicResource`** (metrics and fonts stay `StaticResource`). "system" follows the
  Windows app mode live. Setting persists as `MandarinSettings.Theme`.
- Tool dialogs show the file they will write before the user commits (`OutputPreview` +
  `ToolOutputNaming`); the tools build their real paths from the same helper, so the
  preview cannot drift from reality. A tool that finished but couldn't fully honour the
  request returns `ConversionResult.SucceededWithWarning`, which the HUD shows in place
  of the plain "Done!" subtitle.
- Video/audio work is gated behind `PanelWindow.EnsureFfmpeg`, which opens
  `FfmpegSetupWindow` when ffmpeg is missing and remembers the chosen path in
  `MandarinSettings.FfmpegPath`. Mandarin never downloads it (hard rule 3).
- Dialogs are frosted (Windows 11 acrylic) cards: `DialogCard` + a 46px header strip with
  a `CloseButton` and a centred title, and a `DialogFooterBar` holding the actions, with
  the primary action marked `IsDefault="True"` (the Button style turns that into the
  accent button). Wire the backdrop, header drag and Esc-to-dismiss in one call:
  `DialogChrome.Apply(this, HeaderBar, CardRoot)`.
- **The acrylic backdrop needs a non-layered window**: `AllowsTransparency="False"` plus a
  `WindowChrome` with `GlassFrameThickness="-1"`, and DWM (not the card) draws the rounded
  corners and the shadow — see `Themes/WindowBackdrop.cs`. It degrades to an opaque card on
  Windows 10. A layered window (`AllowsTransparency="True"`) cannot host a backdrop, and it
  also ignores `SetWindowRgn`, so a blur cannot be clipped to a non-rectangular shape: the
  circular radial wheel therefore stays layered and paints its glass with translucent
  fills instead. Windows that animate their own `Opacity` must animate the card instead,
  since a non-layered window can't.

## Commands

- Build: `dotnet build`
- Run: `dotnet run --project src/Mandarin.App`
- Test: `dotnet test`
- Publish (self-contained single exe, the installer's input — see Packaging below):
  `dotnet publish src/Mandarin.App/Mandarin.App.csproj -c Release -r win-x64
  --self-contained true -p:PublishSingleFile=true
  -p:IncludeNativeLibrariesForSelfExtract=true -o publish`
- Build the installer (after the publish step above; needs Inno Setup 6 —
  `winget install JRSoftware.InnoSetup`):
  `"%LocalAppData%\Programs\Inno Setup 6\ISCC.exe" installer\mandarin.iss`
  → `installer-output\MandarinSetup.exe`

## Packaging

Distribution is a self-contained single-file `.exe` (`dotnet publish`, see Commands),
wrapped in an Inno Setup installer (`installer/mandarin.iss`) — no .NET runtime install
required on the target machine. The installer installs per-user to
`%LocalAppData%\Programs\Mandarin` and needs no admin rights or UAC prompt, matching the
app's own no-admin-rights registry usage (Explorer verb, startup entry). It offers a
"start Mandarin when Windows starts" task (checked by default), which writes the same
`HKCU\...\Run` value `Mandarin.Shell.StartupIntegration` writes at runtime from Settings,
so the two stay in sync. Uninstalling removes that value and the Explorer context-menu
verb if either was ever turned on. The installer is unsigned (no code-signing
certificate — same reason MSIX was declined in Phase 6), so Windows SmartScreen shows a
first-run warning; revisit signing if/when there's a purchased cert.
`ffmpeg.exe` is never bundled into the exe, the installer, or the repo — it's a separate
manual step (see Phase 2 in `PLAN.md`) for the same licensing reason bundling FFmpeg needs
a check-in.
